# نطاق الأمان

هذا مشروع ملف أعمال مستقل ببيانات تجريبية، وليس منتجًا خضع لتدقيق أمني مستقل.

## المنفذ

- جلسات دخول بخمول أقصاه 30 دقيقة، وتجديد معرف الجلسة بعد الدخول.
- كلمات مرور مجزأة بـ `password_hash` والتحقق بـ `password_verify`.
- إقفال الحساب 15 دقيقة بعد محاولات دخول فاشلة متكررة (خمس محاولات).
- تحقق CSRF لكل طلب يغيّر البيانات، بما فيه الدخول والخروج.
- صلاحيات على الخادم: مدير (كل العمليات وسجل التغييرات)، محرر (إضافة وتعديل وعرض وتصدير)، قارئ (عرض وتصدير).
- استعلامات PDO مجهزة، قائمة حالات مسموحة، وحدود أطوال المدخلات وحجم JSON.
- عرض النصوص باستخدام `textContent`، وسياسة CSP تمنع السكربتات المضمنة.
- قيد UNIQUE في قاعدة البيانات، ومعاملات SQL تجمع التغيير وسجل التدقيق.
- رقم إصدار للسجل لمنع الكتابة فوق تعديل أحدث، ويشمل الحذف.
- حماية CSV من بادئات الصيغ المعروفة وترميز UTF-8 BOM للعربية.
- لا تُعرض تفاصيل أخطاء قاعدة البيانات للمستخدم.

## قبل النشر العام

1. اجعل جذر الموقع `public/` فقط. لا تعرض المجلد الأب أو ملفات الإعداد أو الاختبارات.
2. استخدم HTTPS واضبط `secure_cookie` على true، وحساب قاعدة بيانات محدود الصلاحيات.
3. لا تستخدم خادم PHP المدمج للإنتاج. اختر Apache/PHP أو خادمًا مناسبًا، وحدّث PHP وMariaDB.
4. أضف حدًا لمحاولات الدخول على مستوى عنوان الشبكة في الخادم العكسي، ومراقبة للأخطاء؛ الإقفال الحالي على مستوى الحساب وقد يُستغل لتعطيل حساب معروف مؤقتًا.
5. ضع أسرار الاتصال خارج Git، وقيّد قراءة الإعدادات وكتابة سجل الأخطاء.
6. اختبر النسخ الاحتياطية واستعادتها واحتفاظ سجل التدقيق؛ لا توجد جدولة نسخ احتياطي مدمجة.
7. أجرِ مراجعة أمنية مستقلة واختبارًا متعدد المستخدمين قبل إدخال أي بيانات فعلية.

سجل التدقيق محفوظ في قاعدة البيانات ويمكن لمدير قاعدة البيانات تعديله؛ ليس سجلًا محصنًا من العبث. إنشاء المستخدمين متاح بأداة CLI فقط. لا توجد استعادة كلمة مرور أو تحقق متعدد العوامل أو مرفقات في هذا الإصدار.
